<objective>
Wire the anonymous-link-view vertical slice end-to-end: a guest opens `/i/[token]`, the handler validates the token + mints an anonymous Supabase session carrying the `plan_id` JWT claim, the guest lands on `/plan/[slug]`, and the server-rendered page reads the plan + members through RLS and displays Surface 3 (anonymous state) per UI-SPEC. This completes the Walking Skeleton's user-visible loop.

Purpose: This plan closes the AUTH-01 + PLAN-03 vertical slice. After this plan, a real user can do something they could not do before: visit a shared invite link without an account and see a plan. This is the "view-only must be feature-complete" half of CP-1 (weakest-link adoption).

Output: One API route + one RSC page tree + 7 components + 4 error pages + 1 rate-limiter + 1 security-headers helper + 1 integration test + 1 un-skipped E2E spec.

User story (MVP_MODE): **As a** guest invited to a plan via WhatsApp, **I want to** open the invite link and immediately see the plan's title and members without making an account, **so that** the friction of joining is removed and I can decide later whether to sign in to participate.
</objective>
