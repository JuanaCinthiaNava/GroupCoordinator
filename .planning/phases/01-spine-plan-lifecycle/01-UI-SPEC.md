# Phase 1 — UI Design Contract: Spine & Plan Lifecycle

> Visual and interaction contract for Phase 1 frontend work. Generated by gsd-ui-researcher.
> Consumed by gsd-ui-checker, gsd-planner, gsd-executor, and gsd-ui-auditor.

**Phase scope:** Auth (Google OAuth + anonymous link-view) + plan create / view / share / revoke / archive / delete + "My plans" list + marketing skeleton.

**Primary viewport:** 375px mobile. All surfaces must render correctly at 375px before addressing 768px and 1024px.

| `--color-destructive` | `#dc2626` | `red-600` | Destructive actions only (revoke, delete) |
| `--color-destructive-foreground` | `#ffffff` | `white` | Text on destructive backgrounds |
| `--color-destructive-subtle` | `#fee2e2` | `red-100` | Destructive tint for confirmation zones |
| `--color-ring` | `#047857` | `emerald-700` | Focus ring color — all focusable elements |

**Accent (`#047857`) reserved for — explicit, exhaustive list:**
1. Primary CTA buttons (filled variant)
2. Focus rings (via `--color-ring`) on all focusable elements
3. Active/selected link state in navigation (underline or left-border indicator)
4. Active plan link in "My plans" list (left-border accent treatment)
5. OG share preview gradient base (via `next/og` route)
6. "Continuar con Google" button in sign-in bottom sheet
7. Checkmarks and radio-selected states in forms

Accent is NOT used on: decorative elements, secondary buttons, hover states for non-primary actions, body text, borders (except active-state borders), icons in default state.

**60 / 30 / 10 split:**
- 60% dominant: `zinc-50` page background + `white` card interiors
- 30% secondary: `zinc-100` surface panels, nav, bottom sheets, settings rows
- 10% accent: emerald-700 on the specific elements listed above

### Typography

**Font loading (Next.js):**
```
import { Geist, Geist_Mono } from 'next/font/google'
const geistSans = Geist({ subsets: ['latin'], variable: '--font-geist-sans' })
const geistMono = Geist_Mono({ subsets: ['latin'], variable: '--font-geist-mono' })
```

CSS variable names: `--font-geist-sans`, `--font-geist-mono`

**Type scale — 4 sizes declared:**

| Role | Size | Weight | Line height | Font | Usage |
|------|------|--------|-------------|------|-------|
| `text-body` | 16px / `text-base` | 400 regular | 1.5 (24px) | Geist Sans | Body copy, list items, form fields, descriptions |
| `text-small` | 14px / `text-sm` | 400 regular | 1.45 (20px) | Geist Sans | Labels, helper text, badges, timestamps, meta |
| `text-micro` | 12px / `text-xs` | 400 regular | 1.4 (17px) | Geist Sans | Fine print, placeholder in full-width inputs only, use-count in token rows |
| `text-heading` | 20px / `text-xl` | 600 semibold | 1.25 (25px) | Geist Sans | Section headings, plan title in header, sheet titles |
| `text-display` | 24px / `text-2xl` | 600 semibold | 1.2 (29px) | Geist Sans | Page-level headings (plan title on plan view hero), dialog titles |
| `text-mono` | 14px / `text-sm` | 400 regular | 1.45 | Geist Mono | Token values, copyable invite links, code snippets |

**Weight rule: exactly 2 weights in Phase 1.** Regular (400) for all body and supporting text. Semibold (600) for all headings, dialog titles, button labels, and the wordmark. No bold (700), no medium (500) — keeping the system clean before Phase 7 polish.

**Line height rule:** body 1.5, headings 1.2–1.25, small/meta 1.4–1.45.

**Minimum accessible text size:** 12px (`text-xs`). Never below 12px for any user-visible string.

### Spacing Scale

Based on 4-point grid. Tailwind utilities listed as implementation reference.

| Token | Value | Tailwind class | Primary usage |
|-------|-------|----------------|---------------|
| `space-1` | 4px | `p-1`, `gap-1` | Icon-to-label gap, inline badge padding, tight list gaps |
| `space-2` | 8px | `p-2`, `gap-2` | Compact button padding (icon-only), chip internal padding |
| `space-3` | 12px | `p-3`, `gap-3` | Small card header internal spacing |
| `space-4` | 16px | `p-4`, `gap-4` | Default card padding (mobile), mobile body horizontal padding `px-4`, form field internal padding |
| `space-5` | 20px | `p-5`, `gap-5` | (reserved — use space-4 or space-6, avoid the middle) |
| `space-6` | 24px | `p-6`, `gap-6` | Section vertical rhythm `space-y-6`, dialog/sheet padding on tablet+, form section gaps |
| `space-8` | 32px | `p-8`, `gap-8` | Page-level top/bottom padding, major section breaks |
| `space-12` | 48px | `p-12` | Major vertical section separators |

**Touch target minimum:** 44px height on all interactive elements (buttons, list rows, token rows) — iOS touch target compliance (HP-4 mitigation).

**Named density rules (from brand decisions):**
- Mobile body horizontal padding: `px-4` (16px)
- Card padding: `p-4` (16px)
- Section vertical rhythm: `space-y-6` (24px)
- List-row min-height: 44px
- Dialog/sheet padding on tablet (md:): `p-6` (24px)

**Exceptions:** None in Phase 1.

### Motion

Durations and easings for interactive elements. Respect `prefers-reduced-motion`.

| Element | Duration | Easing | Tailwind |
|---------|----------|--------|---------|
| Bottom sheet open/close | 300ms | `ease-out` | `duration-300 ease-out` |
| Dialog open/close | 200ms | `ease-out` | `duration-200 ease-out` |
| Toast enter/exit | 150ms | `ease-in-out` | `duration-150 ease-in-out` |
| Button press | 100ms | `ease-in` | `duration-100` |
| Focus ring | 150ms | `ease-out` | `duration-150` |
| Share dialog open (post-create) | 250ms | `ease-out` | `duration-250 ease-out` |

`prefers-reduced-motion` rule: all durations collapse to `0ms` or `1ms` via CSS media query. No structural layout changes — only timing is affected.

## Layout Patterns

### Header (App Chrome)

Used on all `(app)` route group pages. NOT present on `(marketing)` pages.

**Anatomy (left to right at 375px):**
1. `<Logo size="sm" />` — left-most, links to `/me` if authed, `/` if not
2. Plan title (when on a plan route) — `text-heading` (20px semibold), `truncate` at 160px max-width, zinc-950
3. Member avatar stack (when on a plan route) — up to 4 avatars in `rounded-full`, 28px size, overlapping by 8px; "+N" overflow pill if > 4 members
4. RESERVED — search icon slot (Phase 6). Render a 36×36px transparent placeholder `div` with `aria-hidden="true"` and `data-slot="search-reserved"`. Do NOT render a visible icon. This slot holds the Phase 6 global search affordance.
5. Auth affordance (rightmost):
   - Unauthenticated / anonymous: "Iniciar sesión" text link, 14px, zinc-600, triggers sign-in bottom sheet (D-10)
   - Authenticated: avatar (32px, `rounded-full`) + chevron-down → dropdown-menu (account menu: "Mis planes", "Cerrar sesión")

**Responsive:**
- 375px: logo `sm` variant + plan title truncated + avatar stack (max 3) + reserved slot + auth affordance
- 768px (sm:): logo `md` variant, plan title max-width 240px, avatar stack max 5
- 1024px (lg:): logo `md` variant, plan title max-width 400px, full avatar stack

**Header height:** 56px fixed. `sticky top-0 z-sticky bg-white border-b border-zinc-200`.

### Bottom Navigation

Phase 1 has only one primary destination per context: plan view or "My plans". A bottom nav bar with multiple tabs is NOT built in Phase 1. Document the slot for Phase 2+ when the plan gains sub-sections (itinerary, map, votes, notes).

Phase 1 navigation: header only (logo link + auth affordance). If the user needs to navigate "back", rely on browser back or a back chevron in the header for sub-pages (plan settings).

Phase 2 note for planner: when itinerary, map, votes, notes sub-routes are added, implement a bottom tab bar with 4–5 destinations using the UX Pitfalls guidance (bottom nav, not hamburger).

### Modal / Sheet Base Rules

- **Bottom sheets** (`<Sheet side="bottom">`): used for sign-in entry (D-10), any mobile-first complex action. Max-height 85vh. Drag handle visible (4px × 32px pill, zinc-300, centered at top). `rounded-t-lg` on the container.
- **Dialogs** (`<Dialog>`): used for share link (D-07), archive/delete confirmations. Max-width 480px on mobile (full-width minus `mx-4`), 512px on desktop. `rounded-lg`. Backdrop: `bg-zinc-950/60` (60% opacity black).
- **Inline confirm**: destructive actions in token rows use inline expand-to-confirm pattern (Gmail-style), NOT a modal. Row expands to show "¿Seguro? [Revocar] [Cancelar]" in-place.

### Marketing Skeleton (`(marketing)` route group)

Phase 1 ships a minimal landing at `/` — just enough to have a non-404 root. Full landing (hero, how-it-works, features, FAQ) is Phase 7.

Phase 1 marketing skeleton:
- Single page with centered layout
- `<Logo size="lg" />` centered
- Tagline: "Nunca más pierdas la reserva en el chat del grupo." — `text-display` (24px semibold)
- Single CTA: "Crear un plan" → `/plan/new` (or triggers sign-in flow if unauthenticated) — primary button, emerald
- Footer: minimal, "GroupCoordinator · 2026"
- No images, no illustrations, no sections beyond the above

### Props / States

| State | Behavior |
|-------|----------|
| Default | Title field focused on mount, collapsible closed |
| Typing | Title field character count not shown (no limit imposed in v1) |
| Collapsible open | Date + description fields animate in (200ms ease-out) |
| Submitting | CTA button shows spinner, disabled; title field disabled |
| Error — empty title | Inline error below field: "El título del plan es obligatorio." Red border on input (`border-red-500`), no toast |
| Error — server | Inline error at form top (above fields): "Ocurrió un error al crear el plan. Inténtalo de nuevo." |
| Success | Dialog opens immediately (Surface 2) |

### Form Field Specs

**Título (required):**
- `<Input>` shadcn, `rounded-md`, `text-base` (16px), full-width
- Label: "Título del plan" — `text-sm` semibold, zinc-950
- Placeholder: "Ej: Despedida de Carlos en Cádiz"
- Focus ring: `ring-2 ring-emerald-700`

**Collapsible trigger:**
- "Agregar fechas y descripción" — `text-sm`, zinc-600, with chevron-right icon (lucide) that rotates 90° when open
- Touch target: 44px height minimum

**Fecha de inicio / fin:**
- `<Input type="date">` — native date picker; no custom calendar widget in Phase 1
- Labels: "Fecha de inicio" / "Fecha de fin" — `text-sm`, zinc-950
- Helper: "Opcional" — `text-xs`, zinc-500

**Descripción:**
- `<textarea>` (via shadcn `<Textarea>`), 3 rows default, `resize-none`
- Label: "Descripción" — `text-sm`, zinc-950
- Placeholder: "Cuéntale al grupo de qué va este plan..."
- Helper: "Opcional" — `text-xs`, zinc-500

### Responsive

- 375px: full-width form, single column, `px-4` page padding
- 768px (sm:): form centered at max-width 480px
- 1024px (lg:): form centered at max-width 480px (no wider — this is a simple form)

### Accessibility

- `<form>` with `aria-label="Crear nuevo plan"`
- `<fieldset>` wrapping the collapsible section, `<legend>` "Detalles opcionales"
- Title field: `aria-required="true"`, `aria-describedby` pointing to inline error id when error visible
- Submit button: `aria-busy="true"` when submitting
- Focus order: Title → collapsible trigger → (if open) Fecha inicio → Fecha fin → Descripción → Submit
- Error announcement: `role="alert"` on inline error container

## Surface 3: Plan View — Anonymous Viewer State

Implements AUTH-01, PLAN-03, D-08. CP-1 and CP-4 mitigation surface.

### Anatomy

```
[Header — sticky, 56px]
  [Logo sm | Plan title (truncated) | Member stack | RESERVED slot | "Iniciar sesión" link]

[Plan hero — below header]
  [Plan title — text-display (24px, semibold), zinc-950, px-4 pt-6]
  [Date range — if set: "15 jun – 20 jun 2026", text-sm, zinc-500, mt-1 px-4]
  [Creator row — Avatar (32px) + "Creado por [Nombre]", text-sm, zinc-600, mt-3 px-4]
  [Divider]

[Member list section — px-4]
  [Section label: "Participantes ([N])", text-small semibold, zinc-950]
  [Member chip list — flex-wrap gap-2]
    [Each chip: avatar (24px) + first name, rounded-full, bg-zinc-100, px-3 py-1, text-sm]

[Empty state — if plan has no content]
  [Centered vertically within remaining viewport, px-4]
  [Illustration: none — avoid fake placeholder chrome (CP-4)]
  [Copy: "{Creator} sigue agregando detalles. Vuelve pronto." — text-body, zinc-500, text-center]
  [Sub-copy: "Cuando el plan esté listo, lo verás aquí." — text-sm, zinc-400, text-center mt-2]

[Sign-in affordance — bottom of viewport, sticky on mobile]
  [Bar: bg-white border-t border-zinc-200, px-4 py-3, shadow-md]
  [Copy: "Inicia sesión para editar y votar" — text-sm, zinc-600]
  [Button: "Continuar con Google" — emerald filled, 44px height, rounded-md, full-width]
  [Clicking triggers sign-in bottom sheet (Surface 5)]

[Footer — below content, NOT in bottom bar]
  ["Powered by GroupCoordinator" — text-xs, zinc-400, text-center py-4]
  [Virality mechanic per MP-5]
```

### CP-1 pitfall mitigation

**Rule: zero disabled-but-visible edit affordances for viewers.** No grayed-out "Editar" buttons. No locked icons. No "Iniciar sesión para agregar items" placeholders inside content areas. The page must feel complete and intentional as a read-only artifact, not a crippled editor.

**Rule: no Phase 2–5 feature tabs.** Do NOT render "Itinerario | Mapa | Votaciones | Notas" tabs with grayed-out or locked states. Those surfaces do not exist in Phase 1. Rendering them as disabled would imply missing content (CP-4). The plan view in Phase 1 shows only: title, dates, creator, member list, and content state.

### CP-4 empty state copy rule

Empty state copy always assumes the second visitor, not the first. The copy "{Creator} sigue agregando detalles. Vuelve pronto." (D-08) is specific and human. Never use: "No hay contenido todavía", "Vacío", "Sin items", or any generic placeholder. The creator's display name must be resolved and injected into the copy.

### States

| State | Behavior |
|-------|----------|
| Empty plan | Empty state copy shown (D-08 exact copy), sign-in affordance sticky at bottom |
| Plan with future content (Phase 2+) | Content sections appear here; sign-in affordance remains for viewers |
| Long member list (> 8 members) | Member chip list shows first 8 + "+ N más" overflow pill |

### Responsive

- 375px: full-width, single column, sticky sign-in bar visible above any platform chrome
- 768px (sm:): centered content max-width 640px, sign-in bar max-width 640px centered
- 1024px (lg:): centered content max-width 720px, sign-in bar replaced by a sidebar panel (right side, sticky)

### Accessibility

- `<main>` with `aria-label="Vista del plan"`
- Plan title: `<h1>`
- Member list section: `<section aria-label="Participantes">`
- Member chips: each has `aria-label="{name}, participante"`
- Sign-in affordance bar: `<aside aria-label="Iniciar sesión para participar">`
- "Continuar con Google" button: `aria-describedby` pointing to the "Inicia sesión para editar y votar" copy
- Keyboard: sign-in button is focusable and triggers same bottom sheet as tapping

```
      [Left: Google logo SVG (20px) | Center: "Continuar con Google" semibold 16px]
    [Spacer: mt-4]
    [Privacy line: "Al continuar aceptas nuestros Términos de uso y Política de privacidad."

```

### States

| State | Behavior |
|-------|----------|
| Default | Sheet animates up (300ms ease-out), drag handle visible |
| Google button press | Button shows spinner, disabled. Same-tab redirect to Supabase OAuth. |

### Microcopy note

### Accessibility

- `<Sheet>` with `aria-labelledby` pointing to sheet title
- `aria-modal="true"`, `role="dialog"`
- Focus trap inside sheet while open
- First focus on open: "Continuar con Google" button
- Escape key dismisses sheet
- `role="status"` on the spinner for screen reader announcement: "Redirigiendo a Google…"

## Accessibility Baseline

### WCAG AA Compliance

All color combinations used in Phase 1 must meet WCAG AA contrast ratios (4.5:1 for body text, 3:1 for large text and UI components).

| Foreground | Background | Ratio | WCAG AA | Usage |
|-----------|-----------|-------|---------|-------|
| `zinc-950` (#09090b) | `white` (#ffffff) | 19.3:1 | PASS | Primary body text on white |
| `zinc-950` (#09090b) | `zinc-50` (#fafafa) | 18.5:1 | PASS | Text on page background |
| `zinc-500` (#71717a) | `white` (#ffffff) | 4.6:1 | PASS (AA) | Muted text on white |
| `zinc-500` (#71717a) | `zinc-50` (#fafafa) | 4.5:1 | PASS (AA, borderline) | Muted text on background |
| `zinc-600` (#52525b) | `white` (#ffffff) | 7.0:1 | PASS | Muted-foreground text |
| `white` (#ffffff) | `emerald-700` (#047857) | 4.54:1 | PASS (AA) | Text on primary CTA buttons |
| `white` (#ffffff) | `red-600` (#dc2626) | 4.56:1 | PASS (AA) | Text on destructive buttons |
| `zinc-600` (#52525b) | `zinc-100` (#f4f4f5) | 6.2:1 | PASS | Text in surface panels |

Note: `zinc-500` on `zinc-50` is borderline (4.5:1). Use only for decorative/supplementary text where the information is also conveyed through non-color means. For critical muted text (helper text in forms), prefer `zinc-600` on `zinc-50` (ratio 6.5:1).

### Focus Visible Rule

All focusable elements must have a visible focus ring at all times. No suppression of `:focus-visible`. Standard ring: `ring-2 ring-emerald-700 ring-offset-2`. This applies to: buttons, links, inputs, textareas, selects, checkboxes, sheet drag handles.

### Keyboard Navigation

- All interactive elements reachable via Tab key in DOM order
- Bottom sheets: focus trap active while open, released on close, focus returns to trigger
- Dialogs: focus trap active while open, released on close, focus returns to trigger
- Skip-to-main-content link: `<a href="#main-content">` as first element in `<body>`, visually hidden but visible on focus. Text: "Ir al contenido principal"

### Screen Reader Landmarks

App routes must include:
- `<header role="banner">` — sticky header
- `<main id="main-content">` — page content
- `<nav>` for any navigation (header logo link, bottom nav if added later)
- `<footer>` for page footers

ARIA live regions:
- Copy confirmation: `aria-live="polite"` — "¡Link copiado!"
- Form errors: `role="alert"` — immediately announced
- OAuth loading: `role="status"` — "Redirigiendo a Google…"

### Language Attribute

`<html lang="es">` on all Spanish-locale pages. The `[locale]` segment controls this via next-intl's `NextIntlClientProvider` configuration. Do not hardcode `lang="es"` — let next-intl manage it per locale.

## Mobile-First Viewport Rules

**Primary viewport: 375px.** All surfaces designed for 375px first, then progressively enhanced.

| Breakpoint | Tailwind prefix | Min-width | Notes |
|-----------|----------------|-----------|-------|
| Mobile (primary) | (none) | 375px | All surfaces must work here first |
| Tablet | `sm:` | 640px | Note: shadcn/Tailwind `sm:` is 640px, document uses 768px conceptually — use `md:` for tablet layouts |
| Tablet (768px target) | `md:` | 768px | Two-column grids, wider modals, sidebar patterns |
| Desktop | `lg:` | 1024px | Three-column grids, max-width containers |

**Tailwind breakpoint mapping correction:** The design spec above uses 768px as "tablet" — this maps to Tailwind's `md:` prefix (768px), not `sm:` (640px). Use `md:` for all tablet-specific overrides.

**375px compliance rules:**
- No horizontal scroll at 375px on any surface
- All interactive elements minimum 44px height
- All text legible without zooming (`text-base` minimum for body, `text-sm` for labels)
- Bottom sheets and dialogs must not overflow viewport height (max-height: 85vh for sheets)
- Sticky header (56px) + sticky sign-in bar (72px) must not obscure content — ensure `scroll-padding-top` accounts for combined heights

**Test matrix:** Before any surface is considered done, verify at these widths: 375, 390 (iPhone 14 Pro), 414 (iPhone Plus), 428 (iPhone 14 Pro Max), 768 (iPad mini), 1024 (iPad landscape / desktop).

## Pitfall Mitigation: Explicit Cross-Reference

### CP-1 — Weakest-link adoption (hybrid auth, view-only feels complete)

**Addressed in:**
- Surface 3 (Plan View — Anonymous): rule "zero disabled-but-visible edit affordances for viewers"
- Surface 3: rule "no Phase 2–5 feature tabs shown as disabled/locked"
- Surface 4 (Authenticated): sign-in affordance bar hidden from DOM — not just CSS hidden
- All surfaces: read-only mode renders plan content fully, not as a gate preview

### CP-4 — Empty-canvas first-run (empty state copy assumes 2nd visitor)

**Addressed in:**
- Surface 3: empty state copy rule (D-08) with exact prescribed copy `{creator} sigue agregando detalles. Vuelve pronto.`
- Microcopy catalog: `plan.view.empty_heading` and `plan.view.empty_sub` keys use named creator, not generic placeholders
- Surface 3: no grayed-out feature placeholders rendered

### HP-4 — PWA iOS install UX

**Addressed in:**
- Layout Patterns: explicit statement that Phase 1 builds NO install affordance
- Surface 8 (Marketing skeleton): no install prompt, no "Add to Home Screen" nudge
- Mobile-first viewport rules: browser-tab UX is primary; PWA install is Phase 7

### UI Pitfalls table (from PITFALLS.md)

| Pitfall | Mitigation in this spec |
|---------|------------------------|
| Modal-heavy editing on mobile | Sign-in uses bottom sheet (not modal); destructive confirms use inline expand; no heavy editing modals in Phase 1 |
